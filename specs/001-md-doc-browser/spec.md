## User Scenarios & Testing *(mandatory)*

### User Story 1 - Local Folder Registration & File Browsing (Priority: P1)

사용자는 로컬 폴더 경로를 서비스에 등록하고, 해당 폴더 및 하위 디렉토리에 있는 모든 MD 파일의 목록을 트리 구조 또는 계층형 목록으로 확인할 수 있다.

**Why this priority**: 핵심 가치는 흩어져 있는 MD 파일들을 한 곳에서 탐색하는 것이며, 로컬 폴더 지원이 가장 기본 시나리오다.

**Independent Test**: 로컬 폴더를 등록한 뒤 해당 폴더 내 MD 파일 목록이 화면에 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 서비스에 접속해 있을 때, **When** 유효한 로컬 폴더 경로를 등록하면, **Then** 해당 폴더와 모든 하위 폴더의 MD 파일이 계층 구조로 표시된다.
2. **Given** MD 파일 목록이 표시된 상태에서, **When** 사용자가 특정 파일을 클릭하면, **Then** 해당 MD 파일의 내용이 브라우저에서 렌더링된 형태로 표시된다.
3. **Given** 등록된 폴더에 새 MD 파일이 추가될 때, **When** 사용자가 파일 목록을 보고 있으면, **Then** 새 파일이 자동으로 목록에 나타난다.
4. **Given** 사용자가 존재하지 않는 폴더 경로를 등록할 때, **When** 등록을 시도하면, **Then** 명확한 오류 메시지가 표시된다.

### User Story 2 - Remote Path Registration & Browsing (Priority: P2)

사용자는 원격 경로(GitHub 저장소 URL, HTTP/HTTPS URL, 또는 localhost URL)를 등록하고, 해당 위치의 MD 파일 목록을 탐색할 수 있다.

지원하는 원격 경로 유형:
- **GitHub 저장소 URL**: `https://github.com/owner/repo` 형태의 **공개(public) 저장소** (GitHub API를 통해 파일 목록 탐색). 비공개 저장소는 v2 이후 OAuth 기반 인증으로 지원 예정.
- **HTTP/HTTPS URL**: 해당 URL 루트에 `index.json` manifest 파일을 두는 규칙을 따르는 웹 서버 경로
- **Localhost URL**: `http://localhost:PORT/path` 형태의 로컬 서버 경로 (동일하게 `index.json` manifest 규칙 적용)

**Why this priority**: 로컬 파일뿐 아니라 원격 저장소 및 로컬 서버의 문서도 한 뷰어에서 관리하면 활용 범위가 크게 넓어진다.

**Independent Test**: GitHub URL, HTTP URL, localhost URL 각각을 등록한 뒤 MD 파일 목록이 표시되고 클릭 시 내용을 볼 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 GitHub 저장소 URL을 등록할 때, **When** 유효한 URL을 입력하면, **Then** 해당 저장소의 MD 파일 목록이 계층적으로 표시된다.
2. **Given** 사용자가 HTTP/HTTPS URL 또는 localhost URL을 등록할 때, **When** 유효한 URL을 입력하면, **Then** 해당 경로의 MD 파일 목록이 표시된다.
3. **Given** 원격 MD 파일 목록이 표시된 상태에서, **When** 사용자가 파일을 클릭하면, **Then** 원격 파일 내용이 렌더링된 형태로 표시된다.
4. **Given** 원격 경로가 접근 불가능할 때, **When** 사용자가 해당 경로를 등록하거나 탐색하면, **Then** 적절한 오류 메시지와 함께 다른 경로는 계속 사용 가능하다.

### User Story 3 - Beautifully Rendered Markdown View (Priority: P1)

화면은 좌측 사이드바(파일 트리)와 우측 메인 패널(렌더링 영역)로 구성된다. MD 파일 클릭 시 우측 패널에서 GitHub 스타일 또는 이에 준하는 고품질 렌더링으로 내용이 표시된다. 코드 블록 하이라이팅, 이미지, 링크, 테이블 등이 올바르게 표시된다.

**Why this priority**: 단순 텍스트 출력이 아닌 "이쁘게 표시"가 핵심 가치이며 사용자 만족도의 핵심 요소다.

**Independent Test**: 코드 블록, 이미지, 링크, 테이블이 포함된 MD 파일을 클릭했을 때 모든 요소가 올바르게 렌더링되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** MD 파일 목록에서 파일을 클릭했을 때, **When** 콘텐츠가 로드되면, **Then** 제목, 목록, 코드 블록, 테이블, 이미지, 링크가 모두 렌더링된 형태로 표시된다.
2. **Given** 코드 블록이 포함된 MD 파일을 볼 때, **When** 파일이 렌더링되면, **Then** 언어별 문법 강조(syntax highlighting)가 적용된다.
3. **Given** MD 파일 내 다른 MD 파일로의 상대 링크가 있을 때, **When** 사용자가 링크를 클릭하면, **Then** 해당 파일이 뷰어 내에서 열린다.

---

### Edge Cases

- 빈 디렉토리 또는 MD 파일이 없는 폴더를 등록하면 빈 상태 안내 메시지가 표시된다.
- 대용량 MD 파일(수천 줄)이어도 렌더링 성능 저하 없이 표시된다.
- 동일 경로를 중복 등록하려 할 때 적절한 안내가 표시된다.
- 삭제된 파일을 클릭하면 파일이 없다는 안내가 표시된다.
- 파일 이름 또는 경로에 한글/특수문자가 포함되어도 정상 처리된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 로컬 폴더 경로를 하나 이상 등록/삭제할 수 있어야 하며, 등록 정보는 서비스 재시작 후에도 영속적으로 유지되어야 한다.
- **FR-002**: 등록된 경로의 하위 디렉토리를 포함한 모든 MD 파일이 계층 구조로 목록에 표시되어야 한다.
- **FR-003**: MD 파일 목록에서 파일을 클릭하면 렌더링된 내용이 브라우저에 표시되어야 한다.
- **FR-004**: 로컬 경로는 파일 시스템 이벤트를 통해 MD 파일 변경 시 목록이 실시간 자동 갱신되어야 한다. 원격 경로는 사용자 설정 가능한 간격으로 자동 폴링하며, 수동 새로고침 버튼도 제공해야 한다.
- **FR-005**: 원격 경로(공개 GitHub 저장소 URL, HTTP/HTTPS URL, localhost URL)를 등록하고 해당 경로의 MD 파일을 탐색할 수 있어야 한다. GitHub 비공개 저장소는 v2 이후 OAuth 인증과 함께 지원한다.
- **FR-005a**: HTTP/HTTPS 및 localhost 유형의 원격 경로는 해당 URL 루트에 `index.json` manifest 파일이 존재해야 하며, 백엔드는 이 파일을 읽어 MD 파일 목록과 디렉토리 구조를 구성한다. manifest가 없을 경우 사용자에게 안내 메시지를 표시한다.
- **FR-006**: 렌더링은 제목, 목록, 코드 블록(문법 강조 포함), 이미지, 테이블, 링크를 지원해야 한다.
- **FR-007**: MD 파일 내 상대 링크 클릭 시 뷰어 내에서 해당 파일로 이동해야 한다.
- **FR-008**: 경로 등록 실패, 파일 접근 오류 등 예외 상황에 대해 사용자에게 명확한 오류 메시지를 표시해야 한다.
- **FR-009**: 향후 MCP 통합 및 벡터 RAG DB 연동이 가능하도록 확장 가능한 구조로 설계되어야 한다. (v1 구현 범위 외)
- **FR-010**: 서비스는 컨테이너 기반으로 패키징되어 단일 명령으로 실행 가능해야 하며, 프론트엔드와 백엔드를 포함한 전체 스택이 함께 기동되어야 한다.

### Key Entities

- **Source Path**: 등록된 로컬 또는 원격 경로. 고유 식별자, 경로 값, 타입(로컬/원격), 등록 시각, 폴링 간격(원격 전용)을 가지며 서비스 재시작 후에도 영속적으로 유지된다.
- **MD File**: Source Path 하위에 있는 개별 마크다운 파일. 경로, 파일명, 최종 수정 시각을 가짐.
- **Directory Tree**: Source Path 기준 파일/폴더의 계층 구조.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 로컬 폴더를 등록한 뒤 3초 이내에 MD 파일 목록이 표시된다 (폴더당 파일 1000개 기준).
- **SC-002**: MD 파일 클릭 후 2초 이내에 렌더링된 내용이 화면에 표시된다.
- **SC-003**: 등록된 경로에 파일이 추가된 후 5초 이내에 파일 목록이 자동으로 갱신된다.
- **SC-004**: 코드 블록, 이미지, 테이블, 링크를 포함한 표준 MD 파일 100개 중 100개가 오류 없이 렌더링된다.
- **SC-005**: 여러 경로(로컬/원격)를 동시에 등록해도 각각 독립적으로 정상 동작한다.

## Clarifications

### Session 2026-06-30

- Q: HTTP/HTTPS 원격 경로에서 파일 목록을 어떻게 가져오나요? → A: 해당 URL 루트에 `index.json` manifest 파일을 두는 규칙 사용. 백엔드가 이 파일을 읽어 MD 파일 목록을 구성한다.
- Q: GitHub 비공개 저장소를 v1에서 지원하나요? → A: v1은 공개 저장소만 지원. v2에서 OAuth 기반 비공개 저장소 지원 로드맵 명시.
- Q: 파일 목록과 MD 렌더링 패널의 UI 레이아웃은? → A: 좌측 사이드바(파일 트리) + 우측 메인 패널(렌더링) 분할 레이아웃.
- Q: 원격 경로의 파일 변경 감지 방식은? → A: 주기적 자동 폴링(간격 설정 가능) + 수동 새로고침 버튼 병행.
- Q: 서비스 재시작 후 등록된 경로가 유지되어야 하나요? → A: 영속 저장 — 재시작 후에도 등록 경로가 유지되어야 한다.

## Assumptions

- v1 범위는 MD 파일 표시와 탐색에 한정하며, MCP 및 벡터 RAG DB 연동은 v2 이후 확장 기능이다.
- 실시간 파일 감지는 로컬 폴더에 대해서만 v1에서 파일 시스템 이벤트로 지원한다. 원격 경로는 주기적 자동 폴링(기본 간격 사용자 설정 가능)과 수동 새로고침 버튼을 병행 지원한다.
- 파일 검색(search) 기능은 v1 범위에 포함되지 않는다.
- 사용자 인증/권한 관리는 v1에서 지원하지 않으며 단일 사용자 환경을 가정한다.
- 기술 스택(Python vs TypeScript 등) 선택은 플래닝 단계에서 확장성, 생태계, 팀 역량을 고려해 결정한다.
- 서비스는 **Docker Compose 기반 배포**를 처음부터 전제로 설계하며, 프론트엔드·백엔드·향후 추가될 컴포넌트(RAG DB 등)가 모두 컨테이너로 구성되어야 한다.
